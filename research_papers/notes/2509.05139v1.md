## Core Problem & Motivation

ODRL 2.2 is the de facto usage-policy language for data spaces and emerging AI pipelines, but **formal semantics remain a natural-language W3C draft**. Prior formalisations either target older ODRL versions or are partial.

Two operational problems:

1. **Evaluation (monitoring):** given a policy and a *state of the world*, is the policy violated or satisfied?
2. **Comparison:** given a provider policy and a consumer *request policy*, does the request conflict **before** exchange?

Access control is reduced to monitoring if the post-action world can be predicted.

**Gap filled:** a query-answering semantics aligned with ODRL 2.2, plus symmetric/asymmetric comparison via query containment, with reasoning **decoupled** as a materialisation step.

## Architecture / Formalism

### State of the world

World \(\omega\) is a relation of **events**. Event \(e = \langle e_0,\ldots,e_n\rangle\): \(e_0\) timestamp, \(e_1\) action; remaining features are components, constraints, refinements (including count). Feature values: null, constant, or set. \(\gamma_i\) maps feature \(i\) to its ODRL component (Action/Asset/Party) or special \(\rho\) for rule-wide constraints / timestamp.

Null features make **any simple condition on that feature false**.

### Conditions and matching

Simple condition \(\langle i, op, v \rangle\) with operators: `equals`, `gt`, `gteq`, `lt`, `lteq`, `neq`, `isA`/`rdf:type`, `hasPart`, `isPartOf`, `isAllOf`, `isAnyOf`, `isNoneOf`. Complex conditions: \(\land, \lor, \lnot\). **`andSequence` is omitted** (“lack of a clear semantic interpretation”). Negation via exclusive-or: \(\lnot c \equiv c \mathrel{\leftrightarrow} \top\) when features are non-null.

Value comparison grounded in **SPARQL Filter** semantics (type errors → false).

**Well-formed event rule \(\tau\):** (1) specifies Action exactly once; (2) each used core component specified once and not reused in other conditions; (3) each boolean combination uses features of a **single** ODRL component.

\(\mathrm{match}(\tau,e)\) iff all conditions of \(\tau\) hold on \(e\) (boolean query / SQL / SPARQL).

### ODRL Lite — Definition 1 (closed-world, prohibited-by-default)

Policy \(\langle P, F, O \rangle\). \(\omega\) **violates** if:

**Permissions (eq. 1):** \(\exists e\ \omega(e) \land \bigwedge_{\tau\in P} \lnot\mathrm{match}(\tau,e)\)  
(an event exists that no permission matches — *everything not permitted is prohibited*)

**Prohibitions (eq. 2):** \(\exists e\ \omega(e) \land \bigvee_{\tau\in F} \mathrm{match}(\tau,e)\)

**Obligations (eq. 3):** \(\bigvee_{\tau\in O} \nexists e\ \omega(e) \land \mathrm{match}(\tau,e)\)

Combined first-order query: expression (4).

**Default:** prohibited-by-default. Permitted-by-default simulated by a universal permission (top-level action specialisation); limitation: cannot then “carve out” permitted subsets of prohibitions.

Closed-world: missing events are false.

### Full ODRL — Definition 2–3

Extend to \(\langle P, F, O, DP, DPC, FR, OC \rangle\):

| Set | Meaning | Temporal |
|---|---|---|
| \(DP\) | pairs \(\langle \tau, \tau'\rangle\): \(\tau'\) is duty of permission \(\tau\); \(\tau'\) **must be in \(P\)** (spec: obligated party must be able to exercise the Duty Action) | duty event \(e'_0 \le e_0\) |
| \(DPC\) | triples with consequence \(\tau''\) | if duty missing before permission, need later duty **or** later consequence |
| \(FR\) | remedy of prohibition; **prohibition \(\tau \notin F\)** so eq. 2 does not fire independently of remedy | remedy \(e'_0 \ge e_0\) |
| \(OC\) | consequence of missed obligation-by-time; obligation **not** also in \(O\) (else eq. 3 would ignore late fulfilment) | `softmatch` ignores datetime bound |

`softmatch` drops \(\langle\mathrm{Datetime},\le,t\rangle\) from \(\tau\).

### Reasoning (Section 3.3)

Not baked into match. Materialise implied permissions via ODRL Vocabulary `includedIn` (e.g. Play ⊇ Display). Authors **explicitly refuse** to decide whether prohibition of Play implies prohibition of Display (or converse). Obligations/other components similarly unspecified.

### Comparison

Translate policies to queries \(q_p\). \(p \sqsubseteq p'\) iff whenever \(p(\omega)\) then \(p'(\omega)\). Equivalence \(p \equiv p'\).

- **Symmetric conflict (Def. 4):** \(p \not\equiv p'\) (negotiation, no compromise).
- **Asymmetric conflict (Def. 5):** requester \(p_r \not\sqsubseteq p_o\) provider (data sharing: stricter request is OK).

**Consistent normal form (Def. 8):** \(P \not\sqcap F\), \(O \not\sqcap F\), \(O \sqsubseteq P\). Redundant: remove permitted/obliged parts that are forbidden; remove obliged parts that are not permitted. **Prohibitions become redundant** in a consistent policy.

**Theorem 1 (Lite, consistent policies):** \(p \not\sqsubseteq p'\) iff (1) \(P \not\sqsubseteq P'\) or (2) some provider obligation has no requester obligation contained in it.

Vs Bonatti et al.: single constant domain; inferences as materialisation; no nontemporal/temporal left-operand split; **obligations fulfilled by one assignee, not all**; obligation+consequence interpreted; fulfilling events not automatically permitted; finer constraint operators (`isA` vs `isPartOf` vs `isAnyOf`).

## Limitations & Failure Modes

- **Prohibited-by-default** is a design choice, not the W3C `behaviour=open|closed` parameter as later formalised by Mustafa et al. (2606.24344); simulating open/permitted-by-default loses prohibition carve-outs.
- Null features → condition false: open-world *feature* behaviour inside an otherwise closed-world event log.
- `andSequence` omitted; set operators assumed “natural”; `isA` rewritten as `hasPart` on class sets.
- Full ODRL duties/remedies/consequences are FOL-queryable but **Theorem 1 comparison is Lite-only**.
- Action-hierarchy reasoning for prohibitions/obligations left **debated**.
- Obligations: one fulfilling party (simpler, incomplete vs “all assignees”).
- Implementation assumes policies **already consistent**.
- Comparison of full ODRL (duties, remedies) not given a pairwise-rule algorithm.

## Key Takeaways for an NL-to-ODRL system

1. Compile generated policies to **well-formed event rules** (one Action; one specification per core component; boolean combos per-component).
2. Evaluate with **SPARQL/SQL over an event relation**, not ad-hoc if-then.
3. Default to **closed-world + prohibited-by-default** for data sharing; expose permitted-by-default as an explicit universal permission if product requires it.
4. Before comparison/negotiation: **normalise to consistent form** (drop overlapping P∩F, unpermitted O). That is the hook for paper 2603.12926.
5. Use **asymmetric containment** for request vs offer; **symmetric equivalence** only for lock-step negotiation.
6. Materialise action inclusion **separately**; do not silently inherit prohibition along `includedIn`.
7. Encode duty **before** permission (`e'_0 ≤ e_0`); never put remedied prohibitions in \(F\) or consequenced obligations in \(O\).
