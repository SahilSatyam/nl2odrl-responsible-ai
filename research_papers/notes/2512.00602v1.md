# AgentODRL: A Large Language Model-based Multi-agent System for ODRL Generation

- **Paper:** Wanle Zhong, Keman Huang, Xiaoyong Du (Renmin University of China)
- **arXiv:** [2512.00602v1](https://arxiv.org/abs/2512.00602) (29 Nov 2025, cs.MA)
- **Code:** https://github.com/RUC-MAS/AgentODRL
- **Source extract:** `research_papers/extracted/2512.00602v1.txt` (9 pages)

## Core Problem & Motivation

ODRL is the usage-policy lingua franca of data spaces (IDSA, Gaia-X), but authoring it requires RDF, serialisations, and the ODRL conceptual model—an adoption barrier for domain experts. Even with LLMs, translating legal/commercial NL into structurally rigorous ODRL remains a bottleneck.

Prior NL-to-ODRL work is **monolithic**: a single LLM does end-to-end generation, from ontology-guided prompting (Kotis et al.) through Mustafa et al. 2025’s self-correction rules (SCR). The authors argue a single model cannot concurrently (i) parse legal dependencies, (ii) semantically segment policies, and (iii) generate under strict syntax. Performance collapses on **parallel** and **recursive** structures. Training data is scarce (Han et al. 2023).

**Gap filled:** architectural (not just prompt) treatment of NL-to-ODRL, with specialised workers for structural complexity plus post-generation syntactic SHACL loops and LoRA-based semantic reflection.

## Architecture / Formalism

### Use-case complexity model

Core semantic tuple:

```
Rinfo = (P, A, Ac, Cpolicy, Ccontext)
```

where `P` is Party (assigner/assignee), `A` target Asset, `Ac` Action, `Cpolicy` Permissions/Prohibitions/Duties, `Ccontext` contextual Constraints.

| Class | Character | Worker |
|---|---|---|
| **Simple** | Self-contained, no cross-policy dependencies (Ex. 3.1: ShowTimesAPI, Germany, expiry 10 May 2025) | Generator only |
| **Parallel** | Multiple independent policies in one NL text (Ex. 3.2: non-commercial vs commercial drone maps) | Splitter → Generator |
| **Recursive** | Cross-clause referential dependency (Ex. 3.3: Data Security Law of China Art. 48 contingent on Art. 35) | Rewriter → Splitter → Generator |

### Orchestrator–Workers

- **Orchestrator:** classifies input by the above criteria and composes a path.
- **Rewriter:** “Structure-Preserving Inlining”—resolves explicit (clause numbers) and implicit (“Notwithstanding…”) references by inlining referenced content while keeping clause separation, so recursive cases become independent statements for the Splitter.
- **Splitter:** segments on **semantic** shifts only: (1) core asset, (2) assigner–assignee relationship, or (3) fundamental purpose. Then heuristically labels each unit Agreement / Offer / Set.
- **Generator:** produces ODRL, then two quality loops:

**LoRA semantic reflection.** Qwen3-4B-Instruct (BF16) fine-tuned with LoRA (`r=16`, `alpha=32`) on **2,380** synthetic samples, 3 epochs, one NVIDIA 4090. Train loss 0.129, eval loss 0.0668. The small model extracts a structured “semantic checkpoint” list (parties, assets, actions, …). The generator must encode every checkpoint.

**PYSHACL syntax loop.** Generated RDF is validated against ODRL IM/vocabulary SHACL. Error reports are fed back; loop until pass or max **8** reflections (from preliminary experiments).

Paths:

```
Simple:     Input → Orchestrator → Generator → Output
Parallel:   Input → Orchestrator → Splitter → [Units] → Generator → [ODRLs]
Recursive:  Input → Orchestrator → Rewriter → Splitter → [Units] → Generator → [ODRLs]
```

## Evaluation & Benchmarks

### Dataset (new)

Two-stage construction:

1. **70 seeds:** 40 simple / 20 parallel / 10 sequential-dependency, from Mustafa et al. 2025, CESI trusted-data-space drafts, CC 4.0, and manually templated GDPR/CCPA clauses.
2. **Gemini 2.5 Pro augmentation** with “core logic preservation + contextual element transformation”, then manual review.

**770 cases:** 440 simple, 220 parallel, 110 sequential-dependency.

### Metrics

**Grammar Score** (SHACL):

\[
\mathrm{Score_{grammar}}(\%) = \left(1 - \frac{N_{\mathrm{errors}}}{N_{\mathrm{constraints}}}\right) \times 100\%
\]

**Semantic Score** (LLM Jury): an Identifier LLM extracts ground-truth checkpoints from NL; K=2 independent juror LLMs score each unit \(S_{ij}\):

\[
\mathrm{Score_{semantic}}(\%) = \frac{1}{N_{\mathrm{units}}} \sum_{i=1}^{N_{\mathrm{units}}} \left(\frac{1}{K}\sum_{j=1}^{K} S_{ij}\right) \times 100\%
\]

Each configuration run **3 times**, averaged. Models: GPT-4.1, GPT-4.1-mini, GPT-4.1-nano.

### Experiment 1 — generation strategies (Table 1)

Baselines: **OGS** (ontology-guided, Mustafa-style ontology dump) and **SCR-Enhanced** (Mustafa et al. 2025). Ablations: Semantic-Enhanced (LoRA only) vs **AOFP** (full pipeline = LoRA + PYSHACL).

Headline numbers for **ALL use cases**:

| Model | Metric | OGS | SCR-Enhanced | Semantic-Enhanced | AOFP |
|---|---|---|---|---|---|
| GPT-4.1 | Grammar | 82.07 | 93.08 | 93.47 | **99.89** |
| GPT-4.1 | Semantic | 89.59 | 92.00 | 97.78 | **97.93** |
| GPT-4.1-mini | Grammar | 82.41 | 94.83 | 95.44 | **99.36** |
| GPT-4.1-mini | Semantic | 86.53 | 88.93 | 96.25 | **96.43** |
| GPT-4.1-nano | Grammar | 79.77 | 88.40 | 87.49 | **92.01** |
| GPT-4.1-nano | Semantic | 50.51 | 56.23 | 65.67 | **72.35** |

Authors’ claimed deltas vs SCR-Enhanced across the three models: **+5.39%** grammar, **+14.52%** semantic (average). Peak: grammar **+7.32** (GPT-4.1), semantic **+28.67** (GPT-4.1-nano). Recursive GPT-4.1-nano semantics: OGS 34.87 → AOFP **61.53** (+76.46% relative). Average AOFP reflections: 1.29 (4.1), 2.12 (mini), 6.64 (nano); recursive nano **7.32**.

### Experiment 2 — workflow routing (GPT-4.1-nano generator; GPT-4.1 orchestrator/splitter/rewriter)

| Path (ALL cases) | Grammar | Semantic | Reflections | Tokens |
|---|---|---|---|---|
| Generator only | 92.01 | 72.35 | 6.64 | 33,856,708 |
| Splitter → Generator | 93.62 | 84.02 | 5.86 | 47,917,323 |
| Rewriter → Splitter → Generator | **93.27** | **88.07** | 6.09 | 49,451,650 |
| Orchestrator–Workers | 92.56 | 80.22 | 6.04 | **46,209,570** |

Fixed paths set a “theoretical ceiling”; the Orchestrator is slightly below ceiling (80.22 vs 88.07 semantic) but cheaper than always rewriting. Splitter helps **all** categories (parallel semantics 69.44 → 84.88). Rewriter is indispensable on recursive cases (semantic **82.00**).

## Limitations & Failure Modes

- Orchestrator does **not** reach the best fixed path; misrouting remains a residual error.
- Semantic score is an **LLM jury**, not human gold ODRL graphs—circular risk (LLMs judging LLM output).
- Dataset is **synthetic augmentation** of 70 seeds (Gemini 2.5 Pro); distribution may not match messy legal NL.
- Syntax loop max 8; nano still averages 6–7 reflections and grammar only 92% on AOFP ALL (vs ~99% on 4.1).
- No formal policy semantics, conflict detection, or runtime enforcement—generation quality only.
- LoRA expert is trained on the same synthetic methodology as the test set (distribution overlap risk).
- Coverage of ODRL logical operators (`and`/`or`/`xone`), refinements vs constraints, and duties/remedies is not separately reported.

## Key Takeaways for an NL-to-ODRL system

1. **Classify structural complexity first** (simple / parallel / recursive) and route; do not send every policy through the same generator.
2. **Inline cross-references before splitting**; keep clause identity (structure-preserving inlining).
3. **Split on semantic axes** (asset, parties, purpose), not paragraph boundaries; then type as Agreement/Offer/Set.
4. **Decouple syntax from semantics:** SHACL/PYSHACL closed loop for grammar; a specialised extractor (LoRA or rules) as a checkpoint list the generator must cover.
5. **Scale workers with model size:** weaker generators need more reflections; put the strong model on Orchestrator/Rewriter/Splitter and a cheaper model on generation if cost matters.
6. Treat Mustafa et al. SCR as a **baseline**, not the architecture: AgentODRL shows multi-agent routing + validator loops beat SCR on the same cultural/data-space style cases.
