# From Instructions to ODRL Usage Policies: An Ontology Guided Approach

- **Paper:** Daham M. Mustafa, Abhishek Nadgeri, Diego Collarana, Benedikt T. Arnold, Christoph Quix, Christoph Lange, Stefan Decker (Fraunhofer FIT / RWTH Aachen / UPB)
- **Venue:** LLM+KG’24, Guangzhou, 25 Aug 2024; arXiv [2506.03301v1](https://arxiv.org/abs/2506.03301) (3 Jun 2025, cs.CL)
- **Code/data:** https://github.com/Daham-Mustaf/LLM4ODRL
- **Source extract:** `research_papers/extracted/2506.03301v1.txt` (10 pages)

## Core Problem & Motivation

IDSA and Gaia-X rely on ODRL 2.2 for asset usage policies, but domain experts (e.g. cultural sector, Datenraum Kultur) cannot author RDF. Example: “Painting X from Museum M is authorized for display within Germany but prohibited within the USA” requires Asset, Permission, Constraint, etc.

**Gap filled:** end-to-end LLM KG construction **guided by a curated/distilled ODRL ontology + documentation**, plus human-readable **self-correction rules (SCR)**—not raw W3C spec dumps, which confuse models.

Hypothesis: *a curated version of existing ontology documentation will better guide policy generation.*

## Architecture / Formalism

KG construction as \( F(S) \rightarrow KG \) with \( KG = (\mathcal{E}, \mathcal{R}, \mathcal{T}^+) \).

Pipeline (Figure 2):

1. **LLM Guidance Template (LGT)** + **Task Description (TD)** → first ODRL KG.
2. **Self-Correction Model (SCM)** takes TD + first KG + SCR → refined KG.

### Ontology-guided construction

LGT is based on `https://www.w3.org/ns/odrl/2/ODRL22.ttl` (classes, OWL domain/range, SKOS `definition`/`note`/`rdfs:label`). Passing the raw ontology is insufficient: LLMs confuse Action instances with LeftOperands (`odrl:use` as `leftOperand`) and invent properties (`odrl:location` instead of a valid leftOperand).

### OSES Insights (Ontology, Syntax, Semantics, Examples)

The W3C recommendation is distilled because “lengthy explanations and duplicated information” cause hallucinations. Distilled LGT covers:

- **Syntax:** how main entities align.
- **Semantics:** `odrl:Duty` as policy-level **obligation** (`odrl:obligation`) vs permission **condition** (`odrl:duty`).
- **Examples:** real policy fragments.

**Separate LGTs per policy type:** Agreement, Rule, Offer.

### Self-Correction Rules (SCR)

Counts stated: **175 rules for Agreement**, **16 for Offer**, and “ODRL Rule” (wording in the paper is slightly elliptical). Rules are **human-readable**, derived from the W3C recommendation and ontology relations.

Two application modes: iterate one rule at a time vs dump all rules in one prompt (cheaper, “may slightly compromise accuracy”).

**SHACL violation messages alone do not steer the LLM** (stateless; no memory of prior attempts). Unlike SHACL, the LLM can **modify** the KG.

### ODRL coverage in the method

Core IM: Policy (Set / Offer / Agreement), Permission, Prohibition, Duty, Constraint (leftOperand, operator, rightOperand), Parties, Assets. Criteria C1–C9 encode uid, XSD datatypes, Dublin Core meta, assigner/assignee, target, action, at-least-one rule, constraint triple, and profile-mechanism for extensions.

## Evaluation & Benchmarks

- **Dataset:** 12 cultural-domain use cases from Datenraum Kultur (DRK): **4 Agreement, 5 Offer, 3 Set**.
- **Models:** GPT-3.5-turbo, GPT-4, GPT-4o.
- **Methods per case:** Ontology-Guided, OSES Insights, Refinement (SCR). **108 experiments** = 12 × 3 methods × 3 models (36 per model). Each case scored once in the reported exploration.
- **Validation:** hand-authored SHACL: PolicyShape, PermissionShape, PartyShape, AssetShape, ConstraintShape — **22** property ranges for Agreement, **20** Offer, **16** Asset/Set. SHACL Playground + a scoring script. Each focus node / property shape: 1 if pass, 0 if fail.

Accuracy:

\[
\mathrm{Accuracy} = \frac{\sum R}{\sum T} \times 100\%
\]

Headline: Use Case 1 with refinement: **217 / 236 ≈ 91.95%**.

Figure 3 (described, not tabulated per-cell in the extract): Ontology-only is weakest; OSES improves relations/properties; Refinement consistently highest across models and cases. GPT-4 and GPT-4o show similar patterns.

## Limitations & Failure Modes

- **n=12**, single run per configuration—no variance, no complex parallel/recursive legal structure (AgentODRL later scales this to 770 and cites this paper as SCR-Enhanced baseline).
- LGT and SCR are **manually distilled**; authors flag automating extraction from existing KGs as future work.
- Evaluated **only on ODRL** (claimed generic to other ontologies, untested).
- Scoring is SHACL-shape coverage of **criteria**, not graph isomorphism to a gold policy—can reward well-shaped but semantically wrong graphs if shapes are coarse.
- SHACL cannot repair; SCR can, but may over-correct.
- Duty dual role (obligation vs condition) is documented in LGT but not separately scored as a hard semantic test.
- No conflict detection, no comparison semantics, no runtime enforcement.

## Key Takeaways for an NL-to-ODRL system

1. **Never dump the full ODRL TTL + W3C rec into the prompt.** Distill syntax, duty dual-role semantics, and few-shot examples; **split templates by Agreement / Offer / Set**.
2. Keep a **human-readable SCR catalog** derived from the spec (the 175/16 counts are a starting inventory). Prefer iterative rule application if accuracy > cost.
3. **SHACL is a detector, not a teacher.** Feed SCR (or structured error explanations), not raw SHACL reports, back to the LLM.
4. Guard against two systematic hallucinations: **Action used as LeftOperand**, and **invented properties** (`location` vs spatial leftOperand). Encode these as hard SCR items and SHACL node kinds.
5. Criteria C1–C9 + five shapes are a reusable **acceptance test suite** for generated policies.
6. This paper is the **generation-quality floor** that AgentODRL improves; it should remain the ontology/prompting layer inside a Generator worker.
